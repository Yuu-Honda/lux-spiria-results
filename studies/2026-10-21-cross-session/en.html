STUDY / CROSS-SESSION REPLICATION / v1

Fewer false returns.
Fewer relevant hits.

Four further real conversations and 32 queries tested AI-authored retrieval cues and a gate checking returned sources. Relevant-scene hits fell from 7/16 to 5/16. Confusable false returns fell from 6/8 to 0/8.

2026-10-21 · Stored results from a technically amended condition. Browsing does not run the engine or an AI.

Fewer mix-ups are not enough if relevant records are lost.

The retrieval gain observed in an earlier small trial did not replicate on these further conversations. This study found both fewer false candidates and excessive suppression of retrieval.

02 / FAILURE ANALYSIS

The safeguards also suppressed retrieval.

23/32 queries stopped before search

Both AI-cue conditions abstained before search on 10 of 16 positive queries: seven for nonpositive or unknown cue state, two for uncertainty and one for no cues. Past failures and hypothetical consultations can still have relevant records. Local negation or uncertainty should not automatically close the whole retrieval route.

The gate removed three false and one correct candidate

Of nine retrieved candidates, four were rejected: three confusable false candidates and one correct scene. Requiring an exact textual form for a generic paraphrase lost a relevant record. Paraphrase matching needs to be distinguished from person, object and event identity.

Network traversal was not exercised in this study.

Graph expansions, graph edges and associated hits were all zero in every condition. Retrieval used the binary index, but these results do not show an effect of associative traversal or converging paths. Storage and retrieval speed were not timed here.

03 / FIXED INPUTS

Which conversations and procedure were used.

01 Select further conversations

From 171 archived sessions, conversations with recorded use or exposure in eight prior studies were excluded. Eighteen sessions with 8–60 eligible messages were sorted by time and ID; the first four were selected before judging content suitability or performance. The first eight whole messages per session supplied 32 source messages.

02 Build an index from source alone

Eight messages from each conversation formed one scene. An actual AI authored 53 source-only features and another reviewed them; the retrieval inventory contained 52 cue concepts. Indexing did not receive queries or targets and was frozen before query authoring. The endpoint is coarse scene-level retrieval.

03 Retain queries, targets and actual AI choices

Sixteen positive queries (four literal, twelve paraphrase), eight absent and eight confusable queries were authored. A separate step checked all 32 target labels. The cue-authoring AI saw the vocabulary and queries, but not sources, target labels or retrieval results. Actual outputs and reviews were retained.

04 Compare three conditions on fixed inputs

The original-query baseline, AI-cue retrieval and AI cues with a source gate were compared. The latter two shared the same retrieved candidates, isolating the gate. All 32 original labels were scored, with no post-result exclusions or relabeling.

The selection policy is recorded in the work log, but there was no separate on-disk freeze before reading source bodies. Unused means no prior use was found in retained local records; it does not guarantee absence of undocumented exposure or model-training overlap. Roles were separated by instructions on a shared host, not external blinding or access isolation. Model identifiers were unavailable.

04 / RETAINED TECHNICAL FAILURE

Retain the failure and separate the amendment.

Initial condition: technical failure

The source index was saved, but execution stopped on a mismatch with the gate’s stricter evidence contract. One feature included a secondary context quote without its canonical term. This failure is retained; no scored results were observed from that condition.

Separate condition: evidence-only amendment

Only the one context quote was removed, followed by an actual source-only AI review. Source text, feature keys, bit masks and postings stayed unchanged. The same 32 queries, labels and saved AI outputs were reused. Scored results were first observed after this amendment; questions were not freshly authored again.

05 / VERIFICATION

State exactly what replay reproduced.

  • Separate Python processes reproduced retrieval and gate decisions using the same saved AI outputs.
  • A separate recalculation and cold replay checked all 32 queries across three conditions.
  • Seven technical checks passed. Forty-five synthetic engineering checks were separate from the 32 real-source queries.
  • The original failed condition, amendment, source selection, index, queries, actual AI outputs and reviews remain in private frozen records.

The matching runs replayed saved inputs. Regenerating AI interpretations was not tested. Technical checks do not prove retrieval accuracy, personality continuity, affect or brain reproduction. Source checks were internal; public files do not enable independent semantic-index auditing or engine reruns.

07 / IMPLEMENTATION STATUS

Separate study findings from deployment.

LRE: an additive recall route deployed

As of 2026-10-21, canonical private main and the maintained local runtime checkout were updated. AI search hypotheses are added while retaining original-query retrieval. The study’s strict all-or-nothing gate does not replace the existing route. These 32-query results are not deployed-runtime performance measurements.

SHIORI: experimental adapter updated

An explicit adapter using original-source links and an input-evidence preflight were merged into the private experimental branch. SHIORI is not merged into LRE main. The operational SQLite location remains unconfirmed; its update and a full Wake completion have not been established.

Implementation checks and an existing failure

The 83 LRE recall checks and 96 engineering checks including the experimental adapter passed. LRE maintenance reported 467 passes and one existing failure out of 468; the same failure was reproduced on the pre-change canonical version. It concerns generation and continuation-edge consistency in CURRENT documents. Memory was not rewritten to make the check pass.

These are separate implementation validations. They are not pooled with the 45 synthetic study checks, seven technical checks or 32-query outcomes.

08 / NEXT RESEARCH

Next: can relevant recall be recovered?

Separate retrieval from answer adoption

Keep records of negation, failure and hypothetical discussion retrievable, then inspect the returned source before deciding whether it supports an answer.

Separate paraphrases from entity identity

Avoid overconstraining generic paraphrases while checking person, object and event identity within the original source.

Measure network effects and speed separately

Compare traversal and convergence enabled versus disabled, and measure storage and recall timing under matched conditions. Evaluate what this study did not exercise.

Keep these 32 queries as known regression cases. Evaluate improvements on further unused conversations with newly authored queries.

09 / PUBLIC SCOPE AND LIMITS

Retain the limits alongside the result.

  • A small evaluation on four selected conversations, their first eight messages each and 32 research queries; it does not estimate everyday accuracy or support statistical generalization.
  • Causal effects on natural recall, final-answer accuracy, full LRE Wake, Emotion, personality continuity, subjective experience and biological brain reproduction were not measured.
  • Only opaque aggregates and per-query outcomes are public. Original conversations, evidence quotes, queries, native source IDs, feature vocabulary, SQLite, private execution code and detailed logs remain private.
  • The public JSON permits aggregate recalculation. Source auditing and engine reruns require inputs that are not published.
